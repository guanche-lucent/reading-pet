# 产品概述与核心假设

**一句话：**用户上传一本文本型 PDF，系统把它拆成每天 5 分钟的任务卡；用户读完并用自己的话复述一个关键点，就能喂养一只随书中内容成长的宠物（性格与房间受内容影响）。

## 核心假设

| 假设 | 价值 | 验证方式 |
|---|---|---|
| H1 宠物反馈驱动完成 | 「复述一次就能喂养」的即时反馈，能让用户完成原本会拖延的阅读 | 7 天内完成 ≥3 张卡的用户比例（主要指标） |
| H2 宽松判定不制造压力 | 判定从宽（提到一个关键点即通过）比考试式判定更能让人持续 | 复述有效性（护栏指标）+ 退出原因访谈 |
| H3 内容真的影响宠物 | 「房间／性格随书变化」被用户感知到，而不是随机动画 | 访谈中能说清"宠物为什么变"的比例 |

**价值顺序：**先验证 H1（能不能让人真的读三次），再验证 H3（宠物变化是否被理解），H2 全程作为护栏。首批 10 人只能提供方向性信号，**不能证明市场规模**。

# 用户、需求与场景

## 目标用户

成年的自主阅读者（首期以 20–40 岁为主）：手里有想读却没读完的 PDF（专业书、非虚构、课程材料），愿意每天花 5 分钟，但连续打卡式的自律工具对他无效。

**不覆盖**：亲子／儿童朗读场景（涉及儿童隐私、家长同意、语音识别、内容分级，不在本期范围）。

## 用户需求

| 需求类型 | 用户任务 | 产品结果 |
|---|---|---|
| 开始读 | 不知道从哪读起、怕读不完 | 一张只要 5 分钟的任务卡，明确"今天读哪段、要找出什么" |
| 确认读懂了 | 读完不确定自己抓住了什么 | 用自己的话复述一次，得到"我听见你抓住了什么" |
| 获得反馈 | 需要一点即时的正反馈，而不是打卡压力 | 宠物吃到"知识食物"、变化可见 |
| 不丢进度 | 中断后怕要从头来 | 进度、卡片、宠物永不因中断或到期丢失 |
| 长期记得住 | 读过的会忘 | 已掌握／常忘记的概念被记住，到期后用复习卡回顾 |

## 核心场景

1. **每天打开一次**：拿到今天的任务卡，读完 → 复述 → 喂养宠物。
2. **中断后回来**：停了几天回来，卡片和进度还在，宠物没有退化，继续读。
3. **原文已被清理**：停读 7 天后回来，看到"原文已清理，卡片转复习卡"，用记忆复述一次即可。
4. **想接着往下读**：重新上传同一本书 → 系统认出是同一本 → 沿用进度与关键点，只解析未读部分。
5. **不想留数据**：一键删除这本书，进度与宠物记忆一并清除。

# 版本范围与非目标

## P0：必须完成

- 邮箱注册／登录（自存密码哈希，不接第三方）。
- 文本型 PDF 上传与校验（真实类型、大小、页数≤300 / 字数≤20 万、能否提取文本）。
- **上传即解析，解析完成立即删除原文**（原文不留存）。
- 拆书：章节、概念、规则、术语、**每段关键点**（关键点长期保留）。
- 每天一张任务卡：一个明确动作 + 一段节选 + 一道开放式复述题。
- 开放式复述提交 + **宽松判定三态**（通过／不通过／存疑，存疑不计失败不惩罚）。
- 宠物反馈：4 个状态 × 3 个房间主题 = 12 张静态素材；内容标签 → 性格／房间映射。
- 阅读记忆：阅读进度、已掌握、常忘记、上次卡点。
- 原文与解析文本**滚动 7 天到期**（最后一次阅读活动 + 7 天）；到期后卡片转复习卡，**卡片与进度不丢**。
- 一键删除（立即前台不可见，进度与宠物记忆一并清除）。
- 外发确认：书内容送往模型服务前必须有显式确认（一次确认覆盖整本）。
- 埋点与两个核心指标可采集；按环节失败率与重试成功率可查。
- 存疑样本人工复核队列。

## P1：试点后决定

- 微信／Apple 登录、跨设备同步增强。
- 宠物配饰（首版不做；若要加，只加"阅读纪念物"一种，每读完一本得 1 个）。
- 周报／年度回顾、多本书并行。
- 朗读（语音）输入。
- 定时推送提醒。

## 本期明确不做

- 不做打卡、连续天数、排行榜、宠物生病或死亡等惩罚机制。
- 不做实时生成插画（只用预置素材）。
- 不支持 EPUB、DOCX、扫描件 OCR。
- 不在本机离线保存全部数据（数据在云端，见 §9）。
- 不做社交、公开分享、社区。
- 不用模型输出**考试式分数**或对用户能力的评价。

# 核心流程与状态

**正常流程：**登录 → 上传 PDF → 校验 → 解析（原文即删）→ 拆书出关键点 → 生成今日卡 → 用户阅读 → 提交复述 → 宽松判定 → 喂养宠物 + 更新记忆与进度 → 次日新卡。

**到期流程：**最后一次阅读活动 + 7 天 → 解析文本清理 → 卡片转复习卡（无节选，用关键点提问）→ 进度与宠物保留。

## 统一状态

| 对象 | 状态 | 用户可见文案 |
|---|---|---|
| 书 | `uploaded` / `parsing` / `ready` / `failed` / `expired` / `deleted` / `rejected` | "解析中，可以离开"／"解析失败，可重试"／"已按隐私设置清理原文" |
| 任务卡 | `available` / `opened` / `submitted` / `judged` | "今日卡"／"已完成" |
| 判定 | `pass` / `fail` / `uncertain` | "抓住了重点"／"再试一次"／"存疑（不算失败）" |

# 功能需求与验收

| ID | 需求 | 可验收结果 | 异常与边界 |
|---|---|---|---|
| F01 | 注册与登录 | 邮箱 + 密码可注册、登录；密码以哈希存储 | 失败次数限流；不接第三方登录 |
| F02 | 上传与校验 | 接受文本型 PDF；返回页数、字数、解析状态 | 非 PDF／扫描件／超 300 页／超 20 万字 → 明确原因，不进入生成 |
| F03 | 原文不留存 | 解析成功后原文立即删除，界面显示"已清理（不留存）" | 删除失败要有重试与告警，不留半份原文 |
| F04 | 拆书与关键点 | 产出章节／概念／规则／术语与每段关键点，关键点可回溯到页码 | 输出结构非法 → 一次修复重试，仍失败则标失败可重试；**不用模板冒充** |
| F05 | 每日任务卡 | 每天一张：一个明确动作 + 节选 + 一道开放式复述题；点击到出卡 ≤ 90 秒 | 超时／失败要说明原因并可重试；同一页只生成一次（幂等，不重复计费） |
| F06 | 开放式复述 | 用户可写 1–3 句提交；有"今天先到这里"退出选项 | 提交失败不清空输入 |
| F07 | 宽松判定 | 提到本段任一关键点即通过；无法判断输出"存疑"；只可引用已有 keypoint，不得新造 | 系统错误（超时／结构非法／外发被拒）**不算用户失败**，也不进护栏分母 |
| F08 | 宠物反馈 | 判定后宠物状态变化，显示"知识食物 +1"；存疑照样喂 | 宠物永不退化、永不死亡；不因未完成而惩罚 |
| F09 | 房间与性格映射 | 内容标签 + 完成情况 → 3 个房间主题、4 个状态、性格标签；只用 12 张预置素材 | 素材缺失时降级为文字反馈，不报错中断 |
| F10 | 阅读记忆 | 展示进度、已掌握、常忘记、上次卡点 | 只按用户实际表现更新，不做人格推断 |
| F11 | 滚动到期与复习卡 | 停读 7 天后清理解析文本；卡片转复习卡；**进度与宠物保留** | 到期判断在应用侧；存储生命周期仅兜底 |
| F12 | 重新上传同一本书 | 文件指纹相同 → 认出同一本 → 沿用进度与关键点，只解析未读部分 | 指纹不同 → 当新书；续传时外发确认沿用并明确提示，可撤回 |
| F13 | 外发确认与审计 | 首次外发前必须确认；每次外发记录时间、模型、范围标识、确认凭据（**不记正文**） | 无确认 → 直接拒绝，不降级、不静默跳过 |
| F14 | 一键删除 | 删除请求 + 确认凭据 → 立即前台不可见；进度与宠物记忆一并清除 | 缺确认凭据一律拒绝；删除写审计 |
| F15 | 埋点与指标 | 两个核心指标可查询；解析／出题／判定失败率分开统计；重复生成次数恒为 0 | 埋点字段见 §10 |

# 宠物系统规格

| 项 | 规定 |
|---|---|
| 素材总量 | **4 状态 × 3 房间 = 12 张**静态图，本期**不做配饰** |
| 4 个状态 | 饿、吃到知识、消化中、长出了主题物件 |
| 3 个房间主题 | 书房、林间、星夜（名称可调，数量固定） |
| 性格标签 | 6 个内容标签：认知／情绪／方法／故事／数据／关系 |
| 变化规则 | 由「书本内容标签 + 完成情况」决定；**同一本书内不随机跳变** |
| 反馈文案 | 每个状态配 1–2 句温和话术；不使用"你又失败了"这类表述 |
| 禁止 | 宠物生病、死亡、掉级、连续未完成惩罚；用宠物乞求用户回来 |

# AI 能力、知识库与安全

## 架构边界

「本地 PDF 解析 + 受约束模型处理 + 结构化知识 + 规则判定 + 反馈基线」：解析在服务端但不外发；拆书、出题、判定三个环节才外发，且**必须经统一外发出口**（`call_model_service`），每次留审计。

## 关键点与判定

- 关键点**只由拆书阶段产出**，与页码绑定，长期保留（是复习卡与判定的唯一依据）。
- 判定只允许引用已有 keypoint id；结构不符、无法定位关键点、置信不足 → 输出「存疑」。
- 每个复述的判定结果三态落库，用于护栏指标与人工复核。

## 安全与降级

| 情况 | 处理 |
|---|---|
| 未确认外发 | 直接拒绝并提示"需先确认外发"；**不降级为本地模板** |
| 解析／出题／判定失败 | 分类记录失败原因，前台明确告知并给重试入口；重试沿用同一幂等键，不重复计费 |
| 模型不可用／限流 | 说明真实原因，用户可稍后重试；**不用模板结果冒充成功** |
| 书内文本含指令（注入） | 书内文本一律当数据：进入出题／判定前做指令剥离与纯数据封装 |
| 越权访问 | 以 `account_id + book_id` 双因子校验归属，越权拒绝并写审计 |
| 合规到期 | 应用侧先判到期（不可读、不参与出题与判定）；云存储生命周期兜底 |

# 数据对象、权限与生命周期

| 对象 | 关键字段 |
|---|---|
| Account | `account_id`、`login_id`（邮箱）、`password_hash`、`timezone`、`created_at` |
| Book | `book_id`、`account_id`、`file_sha256`、`page_count`、`char_count`、`status`、`uploaded_date`、`last_reading_activity_at`、`parse_text_expire_at`、`original_purged_at` |
| Keypoint | `keypoint_id`、`book_id`、`page_ref`、`text`（**长期保留**，不留原文） |
| TaskCard | `card_id`、`book_id`、`card_date`、`page_start/end`、`goal`、`question`、`keypoint_ids`、`card_kind`（`excerpt`／`review`）、`status` |
| Retelling | `retelling_id`、`card_id`、`attempt_no`、`text`、`submitted_at`、`is_system_error` |
| Judgement | `judgement_id`、`result`（pass/fail/uncertain）、`hit_keypoint_ids`、`model_name`、`latency_ms`、`tokens` |
| Progress/Memory | `reading_progress`、`memory_concepts`（已掌握／易忘／卡点） |
| PetState | `level`、`persona_tags`、`room_theme_id` |
| Audit | `outbound_audit`（外发）、`delete_audit`（删除）、`gen_idempotency`（幂等） |

**生命周期：**

| 数据 | 保留 |
|---|---|
| PDF 原文 | **不保留**（解析完成即删，仅留 `original_purged_at` 审计时间） |
| 解析文本、章节／概念／术语、卡片节选 | 滚动 7 天（最后一次阅读活动 + 7 天） |
| 关键点、任务卡、复述、判定、进度、记忆、宠物状态、审计 | 长期（用户删除时一并清除） |

**权限：**每位用户只能访问自己的书与记录；删除必须显式确认；模型不得自主决定删除、收费或对外分享。

# 埋点与试点指标

## 关键事件

`account_registered`、`book_uploaded`、`book_rejected`（含原因）、`original_purged`、`parse_failed`、`card_generated`、`card_opened`、`retelling_submitted`、`judgement_pass/fail/uncertain`、`pet_changed`、`review_card_shown`、`expired_cleaned`、`resume_uploaded`、`delete_requested`、`retry_succeeded`。

## 指标定义（口径已定，可直接落库）

| 指标 | 口径 | 首轮判断线 |
|---|---|---|
| 主要指标：7 天内完成 ≥3 张卡的用户比例 | 计时起点 = **上传日**；「完成」= 复述已提交且判定**通过**；存疑不计完成；同卡多次提交只算 1 次；分母 = 首轮目标用户数（10） | ≥6/10 继续；4–5/10 优化；<4/10 检查核心价值 |
| 护栏指标：复述有效性 | 判定通过数 ÷ 已提交复述数；分母**含存疑**、**不含系统错误** | ≥70% |
| 到期清理正确率 | 到期后原文／解析文本不可读且卡片转复习卡的比例 | 100% |
| 幂等与成本 | 同一页重复生成次数；单本 token 消耗 | 重复生成 = 0；单本 ≤20 万 token |
| 外发确认覆盖率 | 外发调用中处于有效确认范围内的比例 | 100% |

**样本解释：**10 个用户下，一个人就会明显改变比例。最终判断必须结合行为数据、退出原因访谈与真实复述内容，不能只看单一百分比。

# AI 评测与发布门槛

| 指标 | 建议门槛 | 验证方式 |
|---|---|---|
| 关键点可回溯率 | 100% | 抽查关键点是否都能指回页码 |
| 判定一致性 | ≥85% | 与人工复核结果对比（每周 10–20 条存疑样本） |
| 无依据拒答（关键点为空／无法判定）| ≥90% | 抽取低质量、段末断章样本 |
| 结构化输出合法率 | ≥99% | 含一次修复重试后的 Schema 合法率 |
| 严重问题（原文留存、未确认外发、宠物惩罚、成绩评价）| 0 | 逐条检查与对抗样本 |
| 出卡时延 | P90 ≤90 秒 | 真实模型压测 |

评测集建议：3–5 份小体量文本型 PDF（含标题／表格／图片）+ 1 份扫描件（应明确拒绝）+ 20 条复述样本（含 5 条敷衍输入）。

| 内部 Beta | 真实闭环、异常、删除、到期清理、成本记录全部跑通 | P0 验收通过，无严重问题 |
| 第 0 天 | 10 名用户建档并完成首次上传与首卡 | 激活数据与失败原因完整 |
| 第 1–7 天 | 验证 H1（7 天 3 卡）与 H2（复述有效性） | 指标可查、退出原因有记录 |
| 第 8–28 天 | 验证连续性：中断后是否回来、到期清理是否被理解、宠物变化是否被感知 | 到期事件、回归率、访谈齐全 |
| G1 版本决策 | 结合数据与访谈决定下一步 | 形成 Go／Continue／Pivot／Stop 书面记录 |

## 决策规则

- **Go：**主要指标 ≥6/10、护栏 ≥70%、无严重隐私或安全问题，用户明确表达继续意愿。
- **Continue：**方向成立但某指标或质量未达，限定一轮修复后复测。
- **Pivot：**用户愿意读但不需要宠物反馈 → 转向"每日 5 分钟阅读卡"；或宠物反馈有效但阅读本身不需要拆书 → 转向"轻量复述工具"。
- **Stop：**7 天 3 卡 ≤3/10 且两轮迭代无改善，或出现不可接受的隐私／外发问题。

**Beta MVP 完成定义：**不是页面做完，而是 10 名真实用户在 28 天内能完成上传、每日卡、复述、宠物反馈、到期复习与删除；系统能处理失败、超时、到期与越权；最终形成可审计的数据、评测、访谈与版本决定。
